# Phase 15 — GPU Rendering Backend

## Goal
Connect the validated `RenderFrame` contract to a real graphics API without coupling the engine core to platform windowing.

## Implemented
- OpenGL ES 3.1 public function table for host-provided context entry points.
- `OpenGLESRenderer` consuming the same `RenderFrame` generated by `Renderer`.
- Runtime GLSL ES 3.10 shader compilation and program-link validation.
- Mobile PBR shader using base color, roughness, metallic/specular, emission, opacity, camera, ambient and directional-light inputs.
- GPU vertex/index buffer upload, vertex attributes, indexed triangle drawing, depth testing, back-face culling and alpha blending.
- Opaque-first and back-to-front transparent draw ordering.
- Explicit shader and GPU resource lifecycle/error handling.
- Dependency-free fake-API regression tests so CI validates the complete submission path without a physical GPU.
- Headless rendering remains available as the deterministic validation backend.

## Architecture
```text
Runtime -> Renderer::build_frame() -> RenderFrame
                                      |
                         +------------+------------+
                         |                         |
                    Headless                 OpenGLESRenderer
                                                   |
                                             OpenGLESApi
                                                   |
                                             GLSL ES 3.10
                                                   |
                                               GPU/host
```

The engine does not create an Android EGL display, native window, swapchain or event loop. The host owns the graphics context and presentation lifecycle and supplies the API entry points.

## Checkpoint
- GPU rendering has one public frame contract; there is no parallel scene representation.
- Invalid frames and backend mismatches are rejected before GPU work.
- Shader compile/link/interface errors are surfaced explicitly.
- GPU resources are released on normal paths and allocation failures.
- Transparent geometry is sorted back-to-front.
- The full existing suite plus `exgine_gpu_phase15_tests` is required for completion.

## Production boundary
This is a real OpenGL ES 3.1 rendering path. Android/iOS window creation, EGL lifecycle, presentation, persistent GPU resource caching, texture uploads, shadow maps, post-processing, Vulkan, Metal, D3D12 and platform frame pacing remain explicit future integrations rather than fake implementations.
